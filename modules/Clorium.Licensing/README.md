# 클로리움 라이선스 관리

Windows CameraControl 고객 모듈, 회사용 Windows 관리 앱, 회사/클라우드에서 상시 실행하는 인증 서버입니다. Cryptlex와 같은 핵심 발급·인증 흐름을 자체 구현했으며 Cryptlex의 SDK/서버/코드를 사용하지 않습니다.

## 회사에서 사용하기

1. Windows 서버 또는 회사 PC에 .NET 10 ASP.NET Core Runtime을 준비합니다. 관리 앱 PC에는 .NET 10 Windows Desktop Runtime이 필요합니다. 개발한 이 PC에는 설치돼 있습니다.
2. `company/Start-Server.ps1`을 실행합니다. 소스 폴더에서는 먼저 `Build.ps1`을 실행합니다. 이 작업 PC는 최상위의 `라이선스관리_실행.cmd`로 서버와 관리 앱을 함께 시작할 수 있습니다. 기본 주소는 `http://127.0.0.1:5088`, 데이터 폴더는 스크립트 옆 `.local/company-data`입니다. 서버는 처음 한 번만 서명키와 관리자 인증키를 생성합니다. 데이터 폴더 접근은 실행 계정·SYSTEM·Administrators로 제한합니다.
3. `company/Open-Manager.ps1`을 실행하면 같은 서버의 관리자 키를 자동으로 읽어 연결합니다. 원격 운영은 `-ServerUrl https://실제인증도메인 -AdminTokenFile 회사에서보관한키파일`을 지정합니다. 키는 화면에 표시하거나 고객에게 전달하지 않습니다.
4. 고객사 탭에서 고객사·담당자를 등록합니다. 라이선스 탭에서 영구/데모/테스트, 설치 대수, 허용 주요 버전, 기간을 지정해 발급합니다. 발급된 시리얼을 고객에게 전달합니다.
5. PC 교체는 고객이 먼저 반납하는 방식이 기본입니다. 고장 PC는 선택 후 **강제 회수**를 실행하고 사유를 기록합니다. 회수된 옛 PC는 스스로 다시 인증할 수 없고, 필요하면 회사에서 **재인증 허용**을 실행합니다.
6. 데모/테스트 연장은 **정책·기간 변경**에서 만료일을 바꿉니다. 정식 구매 전환은 종류를 영구로 바꾸면 됩니다. 고객은 기존 설치에서 새로고침하며 사진/설정은 유지합니다.

기본 재확인은 하루에 한 번, 네트워크 장애 유예는 30일입니다. 영구 사용권 자체에 만료일을 넣지 않습니다. 유예기간은 라이선스별 1~365일로 바꿀 수 있습니다. 차단/회수는 다음 서버 확인에 반영되며, 고객 창의 새로고침은 즉시 확인합니다. 기간제의 만료일은 오프라인 유예보다 우선합니다.

## 외부 고객에게 연결하기

인증 서버는 회사 서버/클라우드에서 상시 운영합니다. 공개 도메인과 TLS 인증서를 설정한 HTTPS 역방향 프록시 뒤에 서버를 두세요. 서버 프로세스는 기본 루프백 5088 포트로 두고 외부에는 HTTPS 443만 제공합니다. 프록시는 외부에서 온 X-Forwarded-* 값을 덮어써야 하며, 기본 신뢰 프록시는 루프백입니다. 다른 프록시 주소를 쓸 때는 ASP.NET Core의 신뢰 프록시 설정을 함께 적용해야 합니다.

운영·백업 탭에서 고객 모듈 연결 설정을 내보냅니다. **실제 외부 HTTPS 주소와 운영 서버의 공개키**가 필요합니다. 이 설정을 `Build-Distribution.ps1 -ClientConfig ...`에 넣어 고객용 필수 관리 모드 빌드를 만듭니다. 공개키와 주소는 CameraControl 실행파일 안에 고정되며 설정 파일 삭제로 기존 라이선스 방식으로 내려가지 않습니다.

회사 서버를 다른 PC/클라우드로 옮길 때는 먼저 전체 백업으로 현재 서버의 키와 데이터를 복원합니다. 새 서버에서 새 키를 만들면 이미 빌드된 고객 모듈의 공개키와 달라지므로, 서버 이전은 복원으로 진행해야 합니다. 회사 서버의 비밀 데이터는 배포 ZIP에 자동으로 복사하지 않습니다.

현재 운영 도메인·서버 접근 정보는 제공되지 않았으므로 외부망 배포는 아직 하지 않았습니다. 로컬 확인용 주소를 넣어 만든 후보는 외부 고객에게 배포하지 마세요. 운영 도메인이 바뀌면 기존 고객 실행파일의 주소를 고려해 이전 주소를 유지하거나 새 빌드를 배포해야 합니다.

## 고객 PC에 내장하기

고객 PC는 .NET Framework 4.8과 기존 클로리움 실행 환경을 사용합니다. 새 라이선스 서버용 .NET 10을 고객 PC에 설치할 필요는 없습니다.

- `customer/CameraControl-modules`는 기존 클로리움 런타임에 적용할 교체 모듈입니다. 단독 실행용 전체 설치본은 아닙니다. 고객 설치는 관리자 PowerShell에서 `customer/Install-CameraControl.ps1 -InstallDirectory 기존설치폴더`로 적용합니다. 실행 중이면 거부하고 기존 교체 파일을 별도 백업하며, 오류 시 복원합니다. 촬영·사진·설정 파일은 교체하지 않습니다. 이 스크립트는 `Initialize-CustomerState.ps1`을 호출해 `%ProgramData%\Clorium\Licensing`에 일반 Windows 사용자의 인증 저장 권한을 준비합니다.
- 최초 실행 시 시리얼 입력 후 자동 인증합니다. 이후 실행과 촬영 전에 서명/PC/버전/기간을 검사하고 하루 한 번 서버에서 갱신합니다. **파일 → 라이선스·PC 이전**에서 상태 확인·새로고침·반납이 가능합니다.
- 새 라이선스 모드에서는 기존 `.lock` 및 이미지 EXIF 날짜 제한을 사용하지 않습니다. 이번 소스의 일반 개발 빌드는 설정이 없으면 기존 정식 발급 라이선스 경로를 유지하지만, `Build-Distribution.ps1`의 고객 빌드는 새 모드만 사용합니다.
- 만료/회수 후 새 촬영·외부 셔터 열기를 거부합니다. 이미 진행 중인 다운로드·저장·셔터 닫기를 강제로 끊지 않습니다. 연속 촬영은 다음 컷 진입에서 중단할 수 있고 확보된 원본은 유지됩니다.

라이선스는 Windows 계정마다가 아닌 PC 단위로 관리합니다. 펌웨어 UUID를 우선 사용하며 불가능한 PC는 Windows MachineGuid를 사용합니다. RAM/디스크 교체는 기본 UUID 경로에서 영향을 주지 않습니다. 메인보드 교체나 대체 식별값을 쓰는 PC의 Windows 재설치는 PC 이전/회수 절차가 필요할 수 있습니다.

## 인터넷 없는 PC

1. 고객이 인증 창에서 시리얼을 입력하고 `.clreq` 요청 파일을 저장합니다.
2. 회사 앱의 **오프라인 요청 처리**에서 요청을 선택하고 PC명·버전·시리얼을 확인한 뒤 `.clresp` 응답 파일을 만듭니다. 같은 PC의 재발급은 설치 대수를 중복 사용하지 않습니다.
3. 고객이 응답 파일을 가져오면 해당 PC에서만 활성화됩니다. 요청을 만들었던 PC와 요청 ID가 일치해야 합니다.

일반 오프라인 파일도 설정된 유예 기한을 가집니다. 영구권에서 **무기한 오프라인 허용**을 회사가 명시적으로 선택한 경우에만 무기한 파일을 발급합니다. 데모/테스트는 실제 만료일을 넘기지 않습니다. `.clreq`에는 해당 PC 인증값이 있으므로 담당자에게만 전달하고 공개 게시하지 마세요.

## 백업·복원과 최소 운영

- 서버가 시작 시 및 이후 하루마다 `데이터폴더/backups`에 전체 백업을 만들고 최신 30개를 보관합니다. 백업 실패는 서버 로그에 남습니다. 회사 앱의 **서버 전체 백업 저장**은 수동 백업이며 저장 파일의 ACL도 현재 사용자·SYSTEM·Administrators로 제한합니다.
- 백업에는 고객/발급/설치/이력, 서명 개인키, 관리자 인증 설정, 관리자 키 파일(존재 시)이 포함됩니다. 고객 배포물과 분리하고, 암호화 디스크 및 별도 저장장치/회사 백업 정책으로 보관하세요. 자동 백업은 같은 서버 디스크에 있으므로 서버 전체 손실에 대한 외부 백업을 대신하지 않습니다.
- 복원은 서버를 멈추고 `Restore-Server.ps1 -BackupFile ... -NewDataDirectory ...`로 **새 폴더**에 진행합니다. 기존 폴더를 덮어쓰지 않습니다. `Start-Server.ps1 -DataDirectory 새폴더`로 시작합니다. 개인키를 새로 생성하면 기존 고객 서명을 검증할 수 없으므로 기존 키를 반드시 복원합니다.
- 서비스 운영 계정이 바뀌면 데이터 폴더/백업 접근 권한도 해당 계정에 맞춰 이전해야 합니다. 같은 데이터 폴더에 두 서버를 실행하면 두 번째 서버는 시작하지 않습니다. 다중 서버 동시 쓰기는 지원하지 않습니다.
- 관리 화면에서 고객 검색, 만료 확인, 활성 PC, 마지막 확인일, 변경 사유를 볼 수 있고 CSV로 내보낼 수 있습니다. 오프라인 PC의 버전은 마지막 확인 시점의 정보입니다.

## 검증과 보호 범위

`Build.ps1`로 빌드하고 `Run-Tests.ps1`로 격리된 로컬 서버와 실제 .NET Framework 고객 모듈의 통합·복원 검사를 실행합니다. 테스트는 시험용 고객/PC 지문을 사용하고 실제 카메라로 촬영하지 않습니다. 시험 데이터와 비밀은 `.local`에 보존하며 고객 배포물에 넣지 않습니다.

프로그램 변조, 관리자 권한을 가진 공격자, VM/디스크 전체 스냅샷 복원에 대한 완전한 방어를 보장하지 않습니다. 로컬 시계 역행은 저장된 마지막 확인 시각과 서명 시각으로 탐지하지만 저장소/시간을 함께 되돌리는 공격에는 한계가 있습니다. 완전 오프라인 권한은 회사에서 즉시 회수하거나 실시간 중복 실행을 확인할 수 없습니다. 고가 제품에는 코드 서명·난독화·TPM/하드웨어키 등 별도 보호의 추가 검토가 필요합니다.

이번 범위는 영구/데모/테스트·고객/시리얼/버전/PC·온라인/오프라인·이전/회수·이력/백업입니다. 결제, 리셀러, 동시 접속 좌석, 사용량 과금, SSO, 다중 관리자 역할과 Cryptlex 전체 기능은 포함하지 않습니다.
