# 클로리움라이선스관리 PRD

작성일: 2026-11-02 · 사용자 대화 및 현지 구현/검증 이력 요약 · 저장소: https://github.com/kevinlim360/clorium-g2

## 목적과 범위

Windows용 Clorium CameraControl에 라이선스 모듈을 내장하고 회사용 Windows 관리 앱과 상시 인증 서버로 고객사·시리얼·제품 버전·설치 PC를 관리한다. Cryptlex와 유사한 발급/인증 경험을 목표로 자체 구현했으며 Cryptlex 코드나 SDK를 사용하지 않는다. 판매 규모는 수십 대이며 고객과 회사의 관리 부담을 줄인다.

고객 모듈은 .NET Framework 4.8, 회사 WPF 관리 앱과 ASP.NET Core 서버는 .NET 10이다. 직원 계정은 직원 식별/중지 및 라이선스 연결 레코드이며, 별도 비밀번호 로그인이나 SSO 구현을 의미하지 않는다.

## 확정된 인증 정책

| 대상 | 인증과 사용 | PC 제한 |
|---|---|---|
| 정식 영구권 | 최초 한 번 인증 후 인터넷 재접속 없이 영구 사용 | 인증한 PC와 허용 주요 버전에 한정 |
| 내부 직원 테스트·데모 | 한국시간 달력 기준 3개월마다 서비스에 온라인 재인증 | 직원용도 인증한 PC에서만 작동 |
| 외부 고객 고정 만료 데모·테스트 | 지정 만료일 적용, 기존 일일 확인/최대 30일 장애 유예 유지, 실제 만료일 우선 | 설치 수와 PC 연결 검사 |

직원용은 오프라인 응답 파일로 발급/갱신할 수 없다. 인증 기한 전 새로고침, 재시작, 반납 후 재등록/PC 이전으로 기한이 늘어나지 않도록 서버에 다음 인증일을 저장한다. 기한 이후 온라인 인증하면 해당 인증 시점에서 다음 3개월을 계산한다. 월말·윤년은 달력 계산으로 보정한다. 계정 중지·라이선스 차단 시 재인증을 거부한다. 만료 후에는 다음 촬영을 거부하되 이미 진행 중인 사진 다운로드·저장·셔터 닫기는 완료한다.

이전 30일 확인 토큰은 새 서버/클라이언트를 적용하고 온라인 갱신을 한 번 해야 무접속 영구권으로 전환된다. 과거 PRD의 모든 고객 일일 확인/30일 유예 서술은 이 최신 정책으로 대체한다.

## 기능 요구사항과 수용 조건

- 회사 앱에서 고객사·담당자·직원 ID/이메일, 시리얼, 종류, 설치 대수, 허용 버전, 기간, 설치 PC, 마지막 인증과 이력을 조회·관리한다. 직원 테스트/데모는 3개월 정책을 강제한다.
- 고객은 시리얼 입력으로 최초 인증한다. 실행/촬영 시 서버 서명, PC, 버전, 기간을 로컬 검사한다. 메뉴에서 인증 상태·온라인 재인증·PC 반납을 제공한다.
- 정상 PC 이전은 기존 PC의 온라인 반납을 기본으로 한다. 고장 PC는 회사가 사유와 함께 회수한다. 새 서버로 이전할 때 기존 서명키를 반드시 복원한다.
- 정식 영구권과 외부 고정 기간권에 오프라인 요청/응답 파일 흐름을 제공한다. 요청 ID와 대상 PC를 검증한다.
- 이력·CSV·전체 백업/새 폴더 복원 및 하루 한 번 자동 백업(최신 30개)을 제공한다. 같은 데이터 폴더의 서버 중복 실행을 막는다.
- 고객 배포물에는 공개키와 HTTPS 주소만 넣는다. 서버 개인키·관리자 토큰·고객 DB·백업은 넣지 않는다. 고객 필수 관리 모드에서 설정 삭제로 기존 lock/EXIF 방식으로 우회하지 않는다.

## 구현된 보호와 운영 한계

RSA 3072 서명, PC 지문(펌웨어 UUID 우선/MachineGuid 대체), DPAPI 로컬 저장, Windows/Unix 비밀 파일 접근 제한, 관리자 Bearer 인증, 속도 제한을 구현했다. RAM/디스크 변경은 기본 UUID 경로에 영향을 주지 않지만 메인보드 교체/대체 지문의 Windows 재설치는 이전 절차가 필요할 수 있다.

인터넷에 다시 접속하지 않는 영구권의 즉시 원격 회수와 실시간 중복 실행 탐지는 불가능하다. 강제 회수 후에도 기존 PC의 영구 토큰은 작동할 수 있다. PC/버전 기록은 마지막 인증 시점 정보이다. 관리자 권한 변조, VM/디스크 스냅샷 복원에 완전한 방어를 보장하지 않는다. 직원용도 네트워크 접속 전까지 기존 유효 기한을 즉시 취소할 수 없다. 결제·리셀러·동시접속 좌석·SSO·다중 관리자 역할·Cryptlex 전체 기능은 범위 밖이다.

## 요구사항 변경 이력

1. 상용 PC 소프트웨어 라이선스 시장조사 요청에서 자체 Cryptlex 유사 모듈/회사 관리 앱 제작으로 확정했다.
2. 인증 서버는 개인 작업 PC가 아닌 회사 서버 또는 클라우드에서 상시 운영하기로 했다. 관리 앱은 회사 PC에서 HTTPS로 접속한다.
3. 운영 주소는 `license.clorium.com`으로 선택했다. 등록기관은 가비아, 기존 홈페이지는 카페24이다.
4. 초기 정기 확인 정책을 정식 최초 1회 영구권/직원용 3개월 온라인 재인증으로 변경했다. 직원용의 PC 고정도 명시적으로 요구했다.
5. AWS 계정을 만들고 Lightsail Ubuntu 인스턴스와 고정 IP를 생성했다. 수십 대 규모와 비용을 고려해 월 USD 5/512MB/SSD 20GB로 시작하기로 했다. 실제 Linux 메모리 검증 후 필요하면 상향한다. Agent Toolkit은 필요 없다.
6. DNS 입력 위치 혼동을 확인했다. 가비아에 A 레코드를 저장해도 실제 네임서버가 다른 곳이면 적용되지 않는다. 네임서버 중복 오류는 1~4차에 동일한 `ns1.cafe24.com`을 넣었기 때문이다. 전체 네임서버 변경을 취소하고 실제 DNS 운영처에서 `license`만 설정하도록 안내했다.
7. 2026-11-02: GitHub 보존 및 Claude Code 새 작업 프로젝트 **클로리움라이선스관리**로 이관 요청.

## 운영 인프라와 미완료 사항

대화에서 확인한 AWS 구성: `clorium-license-01`, Sydney `ap-southeast-2a`, Ubuntu, General purpose/Dual-stack, 고정 IPv4 `54.153.232.149`(`clorium-license-ip`). 이전 동적 IP `13.211.154.151`은 사용하지 않는다. 서울 리전 이전은 필수가 아니다.

마지막 실제 DNS 검사에서 `clorium.com`의 권한 네임서버는 카페24 4개였고 `license.clorium.com`은 홈페이지 CNAME 경로로 `222.122.198.189`에 연결되어 있었다. `.co.kr`의 권한 네임서버는 `bns1..4.hostcocoa.com`, `license.clorium.co.kr`은 NXDOMAIN이었다. 이는 이전 검사 결과이며 이관 후 반드시 재조회한다. 가비아 화면에 저장된 A 레코드만으로 공개 DNS 성공을 판단하지 않는다.

의도한 DNS는 카페24의 **A / license / 54.153.232.149**이다. 가비아 전체 네임서버를 바꾸지 않는다. 기존 @/www/MX 및 홈페이지·메일 설정을 유지한다. `.co.kr`를 임의로 카페24로 이전하지 않는다. 방화벽 80/443과 SSH 관리 접근, 서버 서비스 실행, TLS 인증서까지 별도로 확인한다.

Linux 앱 배포·기존 키/데이터 복원·TLS·외부 `/health`·실제 인증 검증은 아직 완료되지 않았다. 현재 최종 고객 후보는 루프백 주소이므로 외부 고객용으로 배포하지 않는다. 운영 URL과 기존 공개키를 넣어 필수 관리 모드로 다시 빌드하고 검증해야 한다. 배포/운영 수용 조건은 `DEVELOPMENT_HANDOFF.md`에 정리한다.
