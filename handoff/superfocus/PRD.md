# 수퍼포커스개발 PRD

갱신: 2026-11-01 · Claude 프로젝트명: **수퍼포커스개발**

## 목적과 개발 기준

기존 Clorium G2의 촬영·저장·API·AutoSizing 호환성을 보존하며, 가까운 곳부터 먼 곳까지 초점이 다른 사진을 순차 촬영하고 하나의 선명한 이미지로 합성한다. 새 제품을 다시 만드는 작업이 아니라 현재 G2 개발 소스를 이어가는 작업이다.

- GitHub: https://github.com/kevinlim360/clorium-g2 · 기준 브랜치: `main`.
- 로컬 루트: `C:\Users\user\Documents\ChatGPT\클로리움G2`.
- 제품: `src/Clorium.G2`, 합성 엔진: `modules/Clorium.Stack`.
- 개발 실행본: `.local/g2-runtime/CameraControl.exe`. 설치본을 덮어쓰지 않는다.
- 이 PRD는 이 대화의 수퍼포커스 요구와 최종 소스·근거를 요약한다. 프로젝트 전체 이력은 `../PRD.md`, `../../work-status.md`, `../../촬영기능_교체현황.md`를 함께 읽는다.

## 사용자 작업 흐름

1. EOS R을 USB로 연결하고 JPEG 단독 사진 모드와 삼각대를 준비한다. 렌즈 스위치는 AF, 본체 Continuous AF는 OFF로 둔다.
2. 라이브뷰 왼쪽 **고스트 바로 위**의 수퍼포커스 버튼으로 이동형 소형 팝업을 연다.
3. 포커스박스를 가까운 피사체로 옮겨 A, 먼 피사체로 옮겨 B를 지정한다. B부터 A 순서도 가능하다.
4. 자동 탐색 중에도 미리보기 박스는 즉시 옮길 수 있다. 반대 지점 버튼은 선택 당시 ROI를 기억해 순차 처리한다.
5. 화살표로 수동 조절하려면 탐색 중에도 누른다. 자동 탐색과 예약 지점을 취소하고 네이티브 AF를 정지한 뒤, 현재 초점을 해당 A/B로 저장하고 수동 이동한다. 이 지점은 탐색 정점 완료를 뜻하지 않는다.
6. A/B 지정 후 입력칸에 고 컷수가 먼저 나온다. 중·저를 선택하면 숫자도 바뀐다. 숫자를 직접 수정할 수 있다.
7. 촬영을 누르면 현재 초점에 가까운 끝점부터 반대 끝점까지 촬영·다운로드·합성한다. 결과 열기 버튼으로 PNG를 확인한다.

## 확정 요구사항

### UI와 입력

- 폭 약 410 DIP의 이동형 팝업. 고정 영상 오버레이를 다시 넣지 않는다.
- 3줄 조작: 초점 화살표/A/B/초기화 → 품질 고·중·저/컷수/포커스박스 → 촬영/중지/결과/고급설정.
- 품질 버튼에는 고·중·저만 표시하고 컷수·간격은 마우스 툴팁으로 표시한다. A/B 상태는 색과 툴팁, 방향은 촬영/컷수 툴팁에 둔다.
- 상세 경로와 설명은 툴팁 또는 접힌 고급설정에 둔다. 닫았다 열어도 같은 카메라 세션의 팝업 위치와 A/B를 보존한다.
- 직접 입력은 정수 **2..고 품질 최대 컷수**, 기존 전체 상한 200을 적용한다. 잘못된 값·빈 편집 상태로 촬영하지 않는다. 직접 입력값이 Refresh나 타이핑 도중 자동값으로 되돌아가지 않아야 한다.
- 앵커 탐색 중에도 컷수와 품질은 편집 가능하다. 화살표는 탐색/수동 이동 중에도 잠그지 않으며 추가 이동은 순서대로 처리한다. 실제 촬영·다운로드 중에는 초점 이동 잠금을 유지한다.

### 초점과 컷수

- A=가까운 초점, B=먼 초점. 숫자는 성공한 작은 SDK 이동의 상대 누적값이며 미터나 광학적 피사계심도가 아니다.
- 수동 화살표는 작은 SDK 명령 1/5/20회. 서로 다른 SDK 이동 크기를 섞어 상대 위치를 잃지 않는다.
- **고: 3작은단계 간격 + 마지막 끝점 포함.** 중=고 컷수 약 2/3, 저=약 1/3 반올림. 최소 2컷이다. 예: A0/B72 → 고25/중17/저8.
- 고의 마지막 나머지 간격은 1 또는 2가 될 수 있다. 직접 컷수는 양 끝을 포함해 범위 전체에 균등 배치한다.
- 이미 현재 끝점에 있으면 A 복귀와 첫 안정화 대기를 생략한다. 이후 이동 안정화와 다운로드 완료 대기는 유지한다.
- 링·줌·렌즈·카메라·장면이 바뀌면 재지정한다. 초점 명령 실패나 위치 불확실 상태를 성공한 범위로 재사용하지 않는다.

### 촬영과 합성

- 하나의 카메라 소유권으로 SDK 작업을 직렬화한다. 다운로드 완료 전에 다음 이동/노출을 하지 않는다.
- 원본 JPEG를 세션별 Superfocus 하위 폴더에 보존한다. 취소 후 늦게 도착한 원본도 보존한다.
- 실패·취소·시간 초과를 정상 합성 완료로 표시하지 않는다. 중지 시 대기 중 A/B·수동 이동을 취소한다.
- 현재 합성은 Python/CPU 8-bit RGB PNG이다. RAW/16-bit/RTX 가속이나 모든 상품의 전 영역 선명도를 보장한다고 표현하지 않는다.
- 기존 고장 난 수퍼포커스/영상 경로는 비활성 상태를 보존한다. 새 동영상 서비스는 미구현이다.

## 사용자 요청과 구현 이력 요약

| 순서 | 요구/문제 | 최종 반영 |
|---|---|---|
| 1 | 기존 수퍼포커스 전송 실패·Device Busy | 순차 소유권, 다운로드 게이트, 콜백 수명/실패 처리, 원본 보존 |
| 2 | 초점 이동이 실제로 보이지 않음 | 사용자 본체 Continuous AF OFF 후 특정 장면 실기 확인 |
| 3 | 라이브뷰 수동 초점·A/B·촬영 버튼 | 1/5/20 이동, 상대 범위와 양 끝 촬영, 직접 촬영 진입 |
| 4 | 박스 이동 시 A/B 초기화 | 측정 ROI와 상대 초점 추적 분리 |
| 5 | 컷수가 너무 많음 | 품질 프리셋 추가 후 고 기준을 1단계에서 3단계로 변경 |
| 6 | 큰 패널이 영상 가림 | 이동형 팝업, 설명/숫자 툴팁, 3줄 압축, 고스트 위 메뉴 |
| 7 | A부터만 촬영해 시간 낭비 | 가까운 현재 끝점부터 A→B/B→A 모두 지원 |
| 8 | 숫자 편집·A 이후 박스 이동 불가 | 기본 캐럿 동작 복원, 탐색 중 편집, 소프트웨어 미리보기 ROI 분리 |
| 9 | A 이후 화살표 장시간 잠김 | 자동 탐색 중단/현재 앵커 저장/수동 이동 큐 전환 |

숫자 직접 입력과 A 이후 박스 이동은 사용자가 정상이라고 확인했다. 마지막 화살표 수동 전환은 비동기 WPF 검사 통과이며 실렌즈 확인은 남아 있다.

## 검증 상태와 미완료

- EOS R + RF24–105mm F4 L IS USM: 이전 특정 장면의 촬영·초점 이동·원본 전송·6720×4480 PNG 합성 성공 기록이 있다. 전체 상품 품질 합격은 아니다.
- 최종 양방향 2컷 실기: `20261028_171944_1ce6fdd9` B→A, `20261028_172028_28fd8e8f` A→B. 총 4 JPEG + 2 PNG 완전 디코딩 기록.
- 수치/촬영 회귀 19묶음, 기존 비활성 경로 19검사, 추가 WPF 비동기 검사 기록을 구분한다. 이번 이관의 재실행 결과는 `CHECKS.md`에서 확인한다.
- 최신 수동 전환은 fake camera/adapter + 실제 WPF Dispatcher 검사다. AF 정지 선행, A 보존, +5/-1 순차 이동, 단일 소유권, 촬영 잠금, 취소를 검사했다. 실제 카메라 광학 검사가 아니다.
- RF24–240, 다양한 상품/초점거리, 최신 수동 전환의 실제 렌즈, 반복 재연결, 최종 설치 배포는 미검증이다.

## Claude의 다음 개발 순서와 완료 기준

1. 새 코드 변경 전에 실제 경로·현재 커밋·PRD·핵심 클래스·검사 근거를 대조한다. 사용자에게 설치본/개발본을 혼동시키지 않는다.
2. EOS R 24–105로 A 선택 직후 박스 이동, 화살표 수동 전환, 숫자 편집, 추가 화살표, 중지를 실제 확인한다. AF/수동 명령이 겹치지 않고 원점/기존 반대 앵커가 보존되는지 기록한다.
3. 같은 범위에서 고/중/저/임의 컷수와 양방향 촬영을 제한된 노출로 확인한다. 예상/실제 컷수, 이동 합계, 원본·PNG 완전 디코딩을 확인한다.
4. 실패·중지·재연결을 확인한 후 RF24–240과 다양한 상품 품질을 확장한다. 모의 검사 성공을 실기 성공으로 대체하지 않는다.

## 범위 밖과 보존 조건

라이선스 관리·이미지 색보정·G2 UI의 별도 변경은 같은 저장소의 독립 기능이다. 이 프로젝트의 첫 작업에서 재작성하지 않는다. F/B/D, PR_F/PR_B, 하자·치수 PR 제외, 폴더/API/AutoSizing, 턴테이블 예외, 기존 CameraPreset 전체 항목을 보존한다.

baseline, ModeVid 복구 참조, 설치 기반 DLL, 개인키/토큰/고객 DB, 원본 사진은 공개 저장소에 넣지 않는다. 일부 빌드 입력은 같은 PC의 무시된 로컬 파일에 의존하므로 Git clone만으로 정식 Windows 실행본을 재현할 수 있다고 약속하지 않는다. 세부 재개 절차는 `DEVELOPMENT_HANDOFF.md`를 읽는다.
