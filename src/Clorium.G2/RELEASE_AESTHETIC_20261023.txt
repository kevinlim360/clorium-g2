Clorium 4.7.1.4 — 미감개선 모드 / 2026-10-23-aesthetic-mode

요청 반영
- 설정 > Custom > 미감개선: 기능 표시/사용 여부를 저장합니다. 기존 설정에는 기본 비활성으로 추가합니다.
- Custom 옵션을 켜면 하자 체크박스 옆에 미감개선 체크박스를 표시합니다.
- 체크 ON: 체크박스의 배경 및 이미지 영역 테두리가 오렌지색입니다.
- 표시 대상: 메인 이미지, 라이브뷰·촬영 미리보기 이미지 영역, 원본/변환 미리보기 이미지.
- 오렌지색은 UI 테두리 표시이며 저장 이미지 픽셀에 칠하지 않습니다.
- 상품이 바뀌어도 모드 상태를 유지합니다. Custom 사용 옵션이 켜져 있으면 프로그램 재실행 시 ON입니다.
- 촬영·저장·썸네일 처리·턴테이블 촬영 중에는 모드 및 Custom 옵션 변경을 잠급니다.
- 몬스타덱 설정·버튼 구현은 사용자 요청에 따라 제외했습니다.

파일명 예시 (ON / OFF)
앞면 원본: C05_32987_001_PR_F.jpg / C05_32987_001_F.jpg
뒷면 원본: C05_32987_001_PR_B.jpg / C05_32987_001_B.jpg
하자 원본: C05_32987_001_D.jpg / C05_32987_001_D.jpg
치수측정용 사진: 치수측정\C05_32987_001_F_M.jpeg (모드와 무관하게 _PR 없음)
치수 결과 사진: 치수측정\C05_32987_001_F_MSize.jpg (_PR 없음)
치수 CSV: 치수측정\C05_32987_001_F_M.csv (_PR 없음)
기존 PR 측정사진을 직접 열어도 새 결과 사진·CSV 이름에서는 PR을 제외합니다.
_PR은 반드시 _F/_B 앞에만 붙습니다. _D, 턴테이블 전용 파일명에는 추가하지 않습니다.
원본·치수 파일의 기존 저장 경로와 기존 측정용 사진 생성 흐름을 유지합니다.
모드 때문에 일반/PR 원본을 두 벌 생성하는 분기는 추가하지 않았습니다.

추가로 재현·수정한 문제
1. 반복 CSV 저장 시 헤더가 빠져 재로드/API 데이터 구성에서 첫 측정값을 놓치는 문제:
   실제 기존 WriteCSV 메서드를 두 번 호출해 재현 후, 헤더와 데이터를 항상 함께 재작성하도록 수정.
2. 바코드 안의 _M/_F 또는 카메라 ID 문자열을 메타데이터 표식으로 잘못 지우는 문제:
   실제 바이너리 검사에서 발견. 선두 카메라 ID와 끝쪽 면/측정 표식만 해석하도록 수정.
3. Windows가 실행 파일을 매핑한 상태에서 덮어쓰기/복원 실패:
   설치 사본에서 실패 포착 후, 일회성 격리 메타데이터 검사와 완성된 임시 파일의 원자적 교체를 적용.
   매핑 조건 및 재적용·복원을 포함한 최종 설치 검사 통과.

Windows 업데이트
파일: Clorium_4.7.1.4_20261023_미감개선_업데이트.exe
1. Clorium 및 AutoSizing을 모두 종료합니다.
2. EXE를 더블클릭하고 관리자 권한 요청을 허용합니다.
3. 기존 설치 폴더를 확인하고 [업데이트]를 누릅니다.
4. 기존 바로가기로 실행한 뒤 Custom > 미감개선을 켜고 설정을 확인/저장합니다.
5. 시험 상품에서 ON/OFF·앞면·뒷면·하자·치수 사진·CSV를 확인합니다.
PowerShell과 별도 압축 해제는 필요하지 않습니다. 기존 PC 업데이트용이며 신규 PC 전체 설치가 아닙니다.
제품 버전 4.7.1.4와 Main/Core 참조 버전 2.1.6.0을 유지했습니다.
AutoSizing 실행 파일도 함께 업데이트해야 하므로 설치 패키지에 포함했습니다.

복원
같은 EXE의 [이전 파일 복원]에서 설치 폴더 UpdateBackups 하위의 이번 백업을 선택합니다.
Main/Core/AutoSizing 및 심볼을 업데이트 전의 정확한 상태로 되돌립니다.
백업 원본 PDB가 없던 설치에서는 복원 시 새 PDB를 제거합니다.
이후 다른 수정본이 적용되었거나 백업이 손상되었으면 덮어쓰지 않고 중단합니다.
고객 설정 JSON의 새 옵션은 남아도 이전 버전은 알 수 없는 새 속성을 무시합니다.

검증 한계와 현장 확인
실제 설치 폴더·고객 라이선스·D: 사진·운영 API에는 쓰기 작업을 하지 않았습니다.
라이선스 검사는 기존 발급 방식과 합성 PC 정보를 사용했고 고객 PC에 원격 접속한 검사가 아닙니다.
WinForms 생성 및 관리자 요청 매니페스트는 검사했으나 UAC 창에서 실제 클릭하지 않았습니다.
실제 카메라/턴테이블/USB/현장 라이선스/API 서버의 전체 업무 흐름은 현장 확인이 필요합니다.
실제 다중 카메라 또는 RAW+JPEG 동시 전송의 콜백 순서도 장치에서 확인해야 합니다.
위 검사가 통과했으며, 프로그램 전체에 어떤 오류도 없다고 보장하는 의미는 아닙니다.
