수정
1. PhotoSession.FormatFileName에서 IsDefect를 FrontBackMode보다 먼저 검사.
2. CaptureOfFrontView의 하자 분기에서 FrontBackMode, GetMeasurePicture, Background 중립화.
3. Main CaptureAsync가 CameraHelper의 false 결과를 전파하고 시작 실패/미연결/예외 시 상태 복구.
4. CameraHelper 장치 예외에서도 모드/측정/배경 상태를 정리.
5. 앞/뒤 촬영이 실패하면 업무 완료 표시를 하지 않음. 배경 촬영의 실패도 상위에 반환.
6. PhotoCaptured finally에서 촬영 상태를 정리한 후 isBtnPressed를 해제.
7. 하자 체크박스는 촬영 진행/썸네일 대기 중 비활성화. 관련 Settings 속성에 변경 알림 추가.
8. 시작 화면 버전 4.7.1.4. 정보창은 제품 버전, 업데이트 비교는 숫자 파일 버전 사용.

검사
- Windows .NET SDK 10.0.400에서 설치본 9프로젝트 및 별도 AutoSizing 대안 전체 빌드 성공.
- WIA 호환성 후처리와 WMPLib 10개 타입/12개 메서드 복원·검증 성공.
- 후처리에서 WMPLib 외 업무 IL 불변 확인.
- 84개 추출 소스 메서드 회귀 검사 통과 (장치/WPF/조명은 대역).
- 실제 후처리 배포 DLL, .NET Framework/WPF에서 19개 검사 통과.
- Windows PowerShell 5.1로 샌드박스 폴더 업데이트/동일 버전 재적용/복원/손상 거부 등 7개 검사 통과.
- 버전·컴파일된 분기·테스트된 메서드 SHA-256 23개 검사 통과.
- 공개 API 비교: Main/Core 모두 누락 0. Core 추가 7개는 WPF 생성 InternalTypeHelper의 타입/메서드.
- Core 내장 리소스는 기존 설치본과 일치. Main 리소스는 수정한 MainWindow XAML에 따라 변경.
- 기존 미사용 변수 및 Android 서버의 대기되지 않은 호출 경고가 남아 있음. 전체 빌드 오류는 0.

테스트가 보장하지 않는 것
실제 카메라/USB, 전체 앱 시작, 현장 설정/라이선스/API, 실제 JPEG 처리, 고객 운영 PC 배포는 미검증.
타임아웃 이후 늦게 도착할 촬영과 다음 작업이 섞이지 않도록 busy를 유지하는 기존 정책을 보존.
지연 이벤트가 영구히 오지 않으면 기존 상태 초기화/연결 복구 절차가 필요할 수 있음.
다중 카메라의 실제 하드웨어 동시 다운로드는 명명 단위 검사와 별개이며 장치 시험이 필요.

전체 소스 사용
Windows 긴 경로 문제를 피하도록 짧은 폴더(예: C:\CloriumSource)에 압축 해제 권장.
  dotnet msbuild Build.proj -m:1 -nodeReuse:false -p:BuildAllVariants=true
배포에 사용할 제품은 build-output/installed의 후처리 결과.
tests/DefectCaptureRegression에 회귀 검사와 근거를 포함.
FILE_MANIFEST.json은 이번 소스 ZIP 기준. FILE_MANIFEST.original-20261005.json은 원본 기록.
기존 deployment의 20261005 설치 소스는 과거 전체 설치 경로이며 이번 증분 업데이트 ZIP과 구분해야 함.
이번 전달은 기존 설치용 업데이트이며 전체 신규 설치 EXE는 새로 만들지 않았음.
