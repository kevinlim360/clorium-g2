# 고객님이 Codex에서 사용할 프롬프트

ZIP을 해제한 뒤 **Build.proj, README.md, FILE_MANIFEST.json이 함께 있는 Clorium_Source_Final_20261005 폴더**를 Codex의 프로젝트로 여세요. 아래 프롬프트를 순서대로 복사해서 사용하시면 됩니다. `[대괄호]` 부분은 아는 만큼 바꾸세요. 개인정보·실제 비밀번호·토큰을 채팅에 붙여넣지 마세요.

이 묶음은 설치본 소스 9프로젝트와 별도 AutoSizing 대안 1프로젝트입니다. 외부/native SDK 전체 소스가 있는 것은 아닙니다. 제공된 DLL과 기존 정품 실행 환경을 함께 유지해야 합니다. 기존 검증은 macOS SDK 10.0.301의 빌드/정적 대조이며 고객 Windows 실행·장치·서버·라이선스·Visual Studio 디자이너는 미확인입니다.

## 2. 전체 빌드

```text
Clorium 복구 소스를 실제로 빌드하고 결과를 확인해 주세요. 원본/작업 상태를 보존하고 별도 작업 사본에서 진행하세요. 제품 EXE·설치 파일 실행, 외부 서비스 인증·접속, 운영 설치 폴더 교체는 이번 요청 범위에 포함하지 않습니다.

README.md와 Build.proj를 읽고 SDK/참조/설정을 확인한 뒤 다음 명령을 소스 루트에서 실행하세요:
dotnet msbuild Build.proj -m:1 -nodeReuse:false -p:BuildAllVariants=true

global.json 기준 SDK 10.0.301 또는 허용되는 후속 feature SDK가 필요하며, 제품 대상 framework는 net48/net472입니다. SDK가 없으면 필요한 버전과 막힌 원인을 명확히 알려주고 가능한 파일/참조 검사를 먼저 진행하세요. 자체 제품 DLL fallback, 빈 구현, 누락 이벤트로 오류를 숨기거나 대상 framework/아키텍처를 임의 변경하지 마세요.

Build.proj의 Main WMPLib/Devices WIA·WinRT 정적 후처리와 해당 PDB를 포함한 결과를 확인하세요. 설치본 결과는 build-output/installed의 9모듈, 대안 AutoSizing은 build-output/standalone의 1모듈입니다. 두 AutoSizing은 출력 EXE 이름이 같아 서로 덮어쓰면 안 됩니다. 각 결과의 SHA·아키텍처·PDB 짝과 실제 오류·경고·명령/SDK를 기록하세요. 고객용 기본 PDB는 이 PC의 소스 경로를 유지합니다. PortableSymbols=true를 선택하면 소스 문서 경로는 /CloriumSource로 매핑되지만 정적 후처리의 CodeView PDB 위치까지 모든 PE 바이트가 같아지는 것은 아닙니다.

같은 원인으로 두 번 실패하면 같은 시도를 반복하지 말고 정확한 오류와 상태를 남겨 방법을 바꾸세요. 빌드 통과 후 무관한 정리/기능 변경은 하지 마세요. 결과 보고는 빌드 성공 여부, 실제 경고, 결과 위치, 남은 확인으로 마무리하세요. 실제 Windows 프로그램·카메라/장치·서버 동작 확인은 빌드 성공과 별개입니다.
```

```text

README-settings.md, config/*provisioning-map.json, tools/InitializeDeploymentSettings와 config/LoadLocalSettings.ps1을 확인하세요. 고객이 보유한 정확한 원본 모듈의 전체 SHA가 매핑과 일치할 때만, 제품을 실행하지 않는 초기화 도구로 기존 직접 문자열 초기값/명시된 문자열 상수를 새 .local JSON에 옮기세요. 원본은 소스 Git/공유 ZIP 밖에 보존하고, 입력을 잘못 골랐거나 출력 파일이 이미 있으면 덮어쓰지 마세요. 실제 값을 확인할 때도 값 대신 성공 여부/필드 수만 보고하세요.

Main 3, Core 1, Plugins 2, AutoSizing 설치본 3/별도본 4의 총 13필드가 매핑돼 있습니다. SMTP 2설정은 고객의 운영 값으로 따로 공급해야 합니다. 라이선스 키를 새로 만들거나 검사를 삭제/우회하지 마세요. 비어 있는 설정을 통신 기능의 빈 구현으로 대체하지 마세요.

LoadLocalSettings.ps1은 JSON 설정을 현재 PowerShell 프로세스 환경에 올립니다. 실제 Windows PowerShell에서 실행/동작이 가능한지 지금 확인하는 검사의 결과를 기존 macOS 정적 검토와 구분하세요. 설정을 올린 같은 프로세스에서 나중에 시작한 프로그램이 값을 상속합니다. 현재 묶음에는 사용자 토큰/운영 설정과 원래 vendor/native runtime 전체가 없으므로 기존 정품 설치 환경의 작업 사본을 별도로 준비해야 합니다. 실제 접속·고객 데이터 사용은 내가 지정하는 검증 환경에서 별도 요청한 경우에 진행하세요.
```
