Clorium 4.7.1.4 추가 수정 및 검증 결과
릴리스: 2026-10-22-session-reset

이번 파일은 2026-10-19에 전달한 4.7.1.4의 제품 전환 오류를 보완한 수정본입니다.
버전은 요청대로 4.7.1.4를 유지하며, 날짜·릴리스 ID·SHA-256으로 이전 패키지와 구분합니다.
어셈블리 참조 버전 2.1.6.0은 유지합니다.

수정한 문제
하자 촬영이 포커스 오류로 실패하면 같은 제품의 재시도를 위해 IsDefect가 유지됩니다.
이 상태로 다음 제품을 생성할 때 하자 상태를 지우지 않아 앞면 촬영이 _D가 되는 문제가 있었습니다.

변경 사항
1. 새 제품 세션을 성공적으로 생성한 뒤 IsDefect, FrontBackMode, GetMeasurePicture, Background를 초기화합니다.
2. 같은 제품의 실패 재시도에서는 하자 선택을 유지합니다.
3. 촬영·저장·썸네일 처리가 끝나기 전에는 새 세션을 만들지 않고 기존 세션을 유지합니다.
4. 메뉴의 새 세션과 바코드 세션 생성이 공통 경로의 가드를 사용합니다.
5. 세션 생성이 차단되면 메뉴와 테스트 촬영 루프가 후속 처리를 진행하지 않습니다.
6. 정상 앞면 _F, 뒷면 _B, 하자 _D 규칙과 기존 하자 우선순위를 유지합니다.

이전 4.7.1.4 대비 수정 제품 소스
projects/CameraControl/CameraControl/ViewModel/MainMenuViewModel.cs
projects/CameraControl/CameraControl/MainWindow.xaml.cs
Core 소스는 이전 릴리스와 동일합니다. 기존 검증 Core DLL/PDB를 그대로 배포합니다.
새로 컴파일한 Core에서는 WPF가 생성한 InternalTypeHelper 타입의 포함 여부 차이가 관측됐습니다.
관련 업무 소스의 변경이 없음을 전수 확인하고, 무관한 공개 타입 변화를 섞지 않기 위해 기존 Core를 선택했습니다.
최종 배포 조합으로 바이너리 검사와 업데이트·복원 검사를 다시 수행했습니다.

검증 결과
- 새 시나리오로 기존 수정본 검사: 163개 중 18개 실패. 제품 전환 결함 재현.
- 추가 수정본: 163개 모두 통과.
- 실제 배포 EXE/DLL·.NET Framework WPF 검사: 51개 통과.
- 업데이트·재적용·롤백·손상·파일 잠금·잘못된 파일 조합 검사: 20개 통과.
- 버전·메서드 소스 해시·컴파일된 분기·세션 가드 연결 검사: 31개 통과.
- 전체 설치본 9프로젝트 및 별도 AutoSizing 대안 빌드 성공.
- WIA 후처리와 WMPLib 10개 타입/12개 메서드 복원·검증 성공.
- 최종 Main/Core 공개 API 누락 0, 추가 0. 내장 리소스 동일.
- 이전부터 존재하던 미사용 변수·디자이너 필드·대기되지 않은 호출 등의 빌드 경고는 남아 있습니다.

주요 시나리오
이전 제품의 앞면/뒷면/하자 촬영 성공 또는 포커스 오류 후 새 제품 생성,
다음 제품의 앞면 _F·뒷면 _B·하자 _D,
8개 제품의 연속 전환과 같은 세션 내 30회 혼합 촬영,
하자 선택만 남은 상태·모든 촬영 플래그가 남은 상태,
같은 제품 하자 재시도, 기본 세션 JSON 설정 로드, 중복 상품 세션 폴더,
촬영 중·썸네일 대기·시간초과 중 세션 전환 차단, 늦은 콜백 후 전환,
폴더 생성 실패 시 이전 작업 상태 유지, 파일명 충돌·덮어쓰기 옵션,
기존 설치 및 이전 4.7.1.4 업데이트, 동일 수정본 재적용,
손상된 업데이트·백업 거부, 교체 중 PDB 잠금에 따른 자동 복원.

검증 범위와 남은 현장 확인
추출 메서드 검사는 장치·조명·일부 UI/설정 저장 의존성을 대역으로 사용합니다.
실제 배포 EXE의 초기화 메서드와 실제 Core 파일명 로직 및 WPF 바인딩도 별도로 실행했습니다.
파일 I/O 검사는 합성 내용이며 실제 카메라 JPEG 다운로드·인코딩 검사가 아닙니다.
전체 CameraControl 실행, 실제 카메라/USB, 현장 라이선스/API는 실행 검증하지 않았습니다.
실제 다중 카메라 또는 RAW+JPG 동시 콜백은 별도 장치 시험이 필요합니다.
검사한 시나리오에서 실패가 없었으며, 프로그램 전체에 다른 오류가 없다고 보장하는 결과는 아닙니다.

추가 요청: 턴테이블 연속 촬영 파일명
기존 Core는 TurnTableShot=true일 때 일반 _F/_B/_D 처리 전에 전용 경로/파일명을 반환합니다.
이 동작을 유지했으며 추가 제품 코드 수정은 필요하지 않았습니다.
실제 배포 DLL에서 단일/다중 카메라 명명 옵션 × 앞뒤 모드 3가지 × 하자 선택 2가지 × 배경 상태 2가지의 24조합을 검사했습니다.
각 조합에서 72컷, JPG/NEF/CR2 입력명 3종(총 5,184회 파일명 생성)이 전용 경로와 정확히 일치했습니다.
배경 상태가 꺼진 12조합에서는 실제 GetNextFileName 경로도 컷별 확인했습니다.
턴테이블 모드 종료 후 일반 앞면 _F, 뒷면 _B, 하자 _D 복귀 3개도 통과했습니다.
전용 파일명 예: M1PRODUCT-L1-01.jpg 또는 M1CAM2_PRODUCT-L1-01.jpg.
장치 없는 검사로는 실제 회전, 중단/타임아웃 뒤 늦게 도착한 이미지 콜백 시점을 검증할 수 없습니다.
이 부분은 현장 턴테이블/카메라로 연속 촬영 중 버튼 선택 및 중단 후 저장까지 확인해야 합니다.
